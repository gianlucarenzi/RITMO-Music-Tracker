# RITMO 2.5 – Raspberry Pi, RISC-V and PowerPC 64: Linux on more architectures

RITMO 2.5 runs on more Linux computers: the Raspberry Pi 3, 4 and 5 with a 64 bit system (aarch64), RISC-V (riscv64) and PowerPC 64 bit big endian (ppc64), besides x86_64. It also fixes two bugs that were found while checking the engine on the big endian machines: RITMO no longer stays silent after an export, and the keys of the keyboard no longer all play a note on the processors where `char` has no sign.

## Downloads

| System | Package | How to start it |
|--------|---------|-----------------|
| Linux x86_64 (Debian 11, Ubuntu 20.04 and newer) | `Ritmo-Linux-x86_64.AppImage` | `chmod +x Ritmo-Linux-x86_64.AppImage`, then run it (needs `libfuse2`; without it add `--appimage-extract-and-run`) |
| Linux aarch64: Raspberry Pi 3/4/5 with a 64 bit system (Raspberry Pi OS 13, Debian 13, Ubuntu 24.04 and newer) | `Ritmo-Linux-aarch64.AppImage` | as the x86_64 one |
| Linux riscv64 (Debian 13 and newer) | `ritmo_2.5_riscv64.deb` | `sudo apt install ./ritmo_2.5_riscv64.deb` (`apt` installs Qt 6 and the other libraries), then `ritmo` |
| Linux riscv64, any distribution | `Ritmo-Linux-riscv64.tar.gz` | unpack it, install the few packages its `README.txt` lists, run `./ritmo` (Qt, PortAudio and RtMidi are inside) |
| Linux ppc64, PowerPC 64 bit big endian (Debian ports, sid) | `ritmo_2.5_ppc64.deb`, `Ritmo-Linux-ppc64.tar.gz` | as riscv64 |
| Windows 64 bit | `Ritmo-Windows-x64-Setup.exe` | **the installer**: Start menu entry, optional desktop icon and `.rmt` file type. It is not signed, so Windows may ask to confirm |
| Windows 64 bit | `Ritmo-Windows-x64.zip` | the same files without the installer: unzip it anywhere and run `Ritmo.exe` |
| macOS 12 or later, Apple Silicon | `Ritmo-macOS-arm64.dmg` | drag `Ritmo.app` to Applications; it is not notarized, so the first time open it with right click → Open |
| macOS 12 or later, Intel | `Ritmo-macOS-x86_64.dmg` | as above; also runs on Apple Silicon through Rosetta 2 |
| All | `Ritmo-User-Manual.pdf` | the user manual |

The riscv64 and ppc64 packages have been built and started (without a display) in an emulator, not on real machines: if you try them, please tell how it went. There are no packages for PowerPC 32 bit and for ppc64le.

## What changed

- **More architectures.** The Raspberry Pi (aarch64) has an AppImage like x86_64. For riscv64 and ppc64 there is a `.deb`, whose dependencies `apt` installs by itself, and a `.tar.gz` with Qt 6, PortAudio and RtMidi inside, for the distributions that do not use `apt`. The user manual explains the installation architecture by architecture.
- **The engine gives the same results on PowerPC.** The songs of the distribution play on ppc64 (big endian) with the same POKEY registers, the same sound and the same screen as on x86_64: this is checked automatically at every change (`scripts/test-endian.sh`).
- **Sound after an export.** Since 2.0 the song timer stayed stopped after an export (SAP, XEX, WAV... from the menu or from a script), so RITMO played nothing until it was restarted. It runs again, and the WAV export starts from a reset POKEY, so its sound does not depend on what played before.
- **Processors where `char` has no sign** (ARM, RISC-V, PowerPC): every key of the keyboard was a note (the "no note" code 0xFF was read as 255), and the undo steps made of several events did not work. Both are fixed.
- **Audio buffer.** Its size is an option of the configuration (`AUDIO_BUFFER_MS`, 5 to 40 ms in the Options dialog): 20 ms by default on Linux, where PipeWire and PulseAudio crackled with 5 ms callbacks, and 5 ms on Windows and macOS. The "Don't use hardware soundbuffer" box is gone: it only changed a flag of DirectSound.

As always, **please tell me how it works for you** by opening an [issue](https://github.com/gianlucarenzi/RITMO-Music-Tracker/issues). The whole list of changes is in the [change history](https://github.com/gianlucarenzi/RITMO-Music-Tracker/blob/master/doc/rmt_changes.md).
