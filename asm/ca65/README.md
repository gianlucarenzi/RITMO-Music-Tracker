# The RMT 6502 sources for ca65 (cc65)

The 6502 sources of `asm/` are written for MADS (Patch-16) and XASM (Legacy). This folder has the same sources
for ca65, the assembler of [cc65](https://cc65.github.io/), so that the RMT drivers and players can be built where
MADS is not installed:

```bash
cd asm/ca65
make            # build/rmt_driver_v6.obx, rmt_driver_v1.obx, rmt_sap4.obx, rmt_sap8.obx, rmt_msx.obx, rmf_play.xex
make check      # the drivers must be byte for byte those of rmt/resources/drivers
```

It needs `ca65` and `ld65` (cc65 2.19 or later), `make`, `awk` and a POSIX shell.

## The files

| File | |
|------|-|
| `Legacy/*.s`, `Legacy/rmf/*.s`, `Patch-16/*.s` | the sources, one for each `*.a65` / `*.asm` of `asm/` |
| `mads.inc` | `ORG`, `OPT_H`, `RUN`, `INI`: the Atari binary file as MADS writes it |
| `obx.sh` | `obx.sh out.obx source.s [ca65 options]`: assembles one source into an Atari binary file; with `OBX_SYMBOLS="name ..."` it also prints `OBX_SYMBOL name XXXX` for each symbol |
| `obx.cfg` | the ld65 configuration of `obx.sh` |
| `Makefile` | the targets below |

The `.s` files are generated by `scripts/mads2ca65.py` from the MADS sources: change the MADS source, then
`make sources` (or `python3 scripts/mads2ca65.py` from the top folder) writes the `.s` files again. Each `.s` file
says which source it comes from. The binary files the sources include (`ins`: `font.fnt`, `music.rmt`,
`test.rmf`) are read from the MADS folder, they are not copied here.

## Targets

| Target | Source | Check |
|--------|--------|-------|
| `build/rmt_driver_v6.obx` | `Patch-16/rmtplayr.s` (RMT 1.34 Patch16, `rmt_feat` as it is: `FEAT_IS_TRACKER`) | identical to `rmt/resources/drivers/rmt_driver_v6.obx` |
| `build/rmt_driver_v1.obx` | `Legacy/rmt_ata.s` (RMT 1.28) | identical to `rmt/resources/drivers/rmt_driver_v1.obx` |
| `build/rmt_sap4.obx`, `rmt_sap8.obx` | `Legacy/rmt_sap4.s`, `rmt_sap8.s` (SAP players of RMT 1.28, 4 and 8 tracks) | the sources check (`ert`) that the player ends at the address of the original ($394E, $3A5A) |
| `build/rmt_msx.obx` | `Legacy/rmt_msx.s` (XEX player routine of RMT 1.28) | assembled, no reference |
| `build/rmf_play.xex` | `Legacy/rmf/rmf_play.s` (RMF player with `test.rmf`) | assembled, no reference |
| `make players`: `build/rmtplayer.xex`, `rmtplayer.sap` | `Patch-16/rmtplayer.s` (Simple RMT Player with `music.rmt`, XEX or SAP) | the SAP played on the 6502 of RMT gives the POKEY registers of the Patch16 driver of RMT, frame by frame |
| `make players`: `build/rmtvis.xex` | `Patch-16/rmtvis.s` (RMT Visualizer with `music.rmt`) | assembled, no reference |

The players are assembled with `FEAT_IS_TRACKER=0` and `FEAT_IS_SIMPLEP=1` (the player routine at $3100); with
MADS these are the values to set in `rmt_feat.a65`. The SAP export and the "XEX + LZSS driver" export of RITMO do not
use these players: they use `rmt/resources/players/vu_player_v2.obx` (VUPlayer, from
https://github.com/VinsCool/VUPlayer-LZSS) and the LZSS streams. The "XEX + RMT player" export uses the players of
`asm/rmtplay` (`Legacy/rmt_xex.s` and `Patch-16/rmtplayr.s`, assembled by `obx.sh`, with the visualizer of RMTPLAY).

The feature switches and the configuration symbols (`FEAT_*`, `STEREOMODE`, `EXPORTXEX`, `EXPORTSAP`, `VLINE`,
...) can be given to `obx.sh` as ca65 options, for example `-D FEAT_IS_TRACKER=0 -D FEAT_IS_SIMPLEP=1`: their
definitions in the sources apply only when the symbol is not defined yet.

## How the translation works

| MADS / XASM | ca65 |
|-------------|------|
| `label`, `label equ x`, `label org *+n` | `label = *`, `label = x`, `label = *` and `ORG *+n` |
| `org a`, `opt h-` / `h+`, `run a`, `ini a` | `ORG a`, `OPT_H 0` / `1`, `RUN a`, `INI a` (`mads.inc`) |
| `icl "f.a65"`, `ins "f"` | `.include "f.s"`, `.incbin "f"` |
| `IFT` `ELI` `ELS` `EIF`, `ERT c` | `.if` `.elseif` `.else` `.endif`, `.assert !(c), error` |
| `dta b(..) a(..) l(..) h(..)`, `c"text"`, `d"text"`, `"text"*` | `.byte`, `.word`; strings as ATASCII, ANTIC internal codes (`d`), inverse (`*`) |
| `[ ]` `==` `!=`, `asl @`, `lda #-1` | `( )` `=` `<>`, `asl a`, `lda #<(-1)` |
| `:4 sta mis+#,x` | `.repeat 4, I` / `sta mis+I,x` / `.endrep` |
| `mva`, `mwa`, `mwx`, `add`, `sub`, `jeq` ..., `scc:inc`, `mva:rne`, `sta a,x+`, `lda <a` | the 6502 instructions they stand for, after the MADS line as a comment |

Labels become `label = *`: then a label in page zero gives zero page addressing, as in MADS (a ca65 label in a
segment would be absolute). ca65 runs with `-i`: names are not case sensitive, as in MADS.

MADS writes `$FFFF`, then a header (start, end) and the bytes for each `org`; it leaves out a segment without
bytes and continues the segment when an `org` is where the previous one ended. `ORG` does the same, but a header
comes before the bytes and whether a segment is empty is known only at its end, so `obx.sh` assembles twice: the
first time ca65 prints `OBX_EMPTY <n>` for each empty segment, the second time those segments get no header.
After `opt h-` no `$FFFF` is written (`sap.asm` writes it itself after the SAP text).

Where no binary checks the translation, the pseudo instructions follow the MADS manual; the order of the
instructions could differ from MADS where it does not change the result (`mva src,x+ dst,y+` is `lda`, `sta`,
`inx`, `iny`), and `jeq` and the other long branches are always `bne *+5` / `jmp`.
