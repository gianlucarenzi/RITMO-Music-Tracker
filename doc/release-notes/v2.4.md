# RITMO 2.4 – a lighter screen: less CPU, smooth sound on slow computers

RITMO 2.4 draws its screen with a fraction of the work it needed before. On a slow computer this leaves the processor to the sound: the glitches and the drops of the frame rate while a song plays are gone, and the program stays almost idle when the song is stopped.

## Downloads

| System | Package | How to start it |
|--------|---------|-----------------|
| Linux x86_64 (Debian 11, Ubuntu 20.04 and newer) | `Ritmo-Linux-x86_64.AppImage` | `chmod +x Ritmo-Linux-x86_64.AppImage`, then run it (needs `libfuse2`; without it add `--appimage-extract-and-run`) |
| Windows 64 bit | `Ritmo-Windows-x64-Setup.exe` | **the installer**: Start menu entry, optional desktop icon and `.rmt` file type; for all the users or for the current one. It is not signed, so Windows may ask to confirm |
| Windows 64 bit | `Ritmo-Windows-x64.zip` | the same files without the installer: unzip it anywhere and run `Ritmo.exe` |
| macOS 12 or later, Apple Silicon | `Ritmo-macOS-arm64.dmg` | drag `Ritmo.app` to Applications; it is not notarized, so the first time open it with right click → Open |
| macOS 12 or later, Intel | `Ritmo-macOS-x86_64.dmg` | as above; also runs on Apple Silicon through Rosetta 2 |
| All | `Ritmo-User-Manual.pdf` | the [user manual](https://github.com/gianlucarenzi/RITMO-Music-Tracker/releases/download/v2.4/Ritmo-User-Manual.pdf) |

Everything the program needs is inside each package.

## What changed

- **Only what changes is drawn.** The tracker still describes its whole screen 60 times a second, but the drawing calls are now recorded and compared with those of the previous frame: only the parts of the screen where they differ are drawn, and only those parts are sent to the display. What you see is exactly the same, pixel for pixel.
- **Less work when nothing happens.** When the song is stopped, no note is sounding and you are not typing or moving the mouse, the screen is refreshed 10 times a second instead of 60; any key, click or note brings it back to full speed at once.
- **The numbers**, measured on a Celeron N3060 (two cores at 1.6 GHz), as the share of one core:

  | | 2.3 | 2.4 |
  |---|---|---|
  | song playing | 45 % (and the X server about as much again) | 32 % (the X server only for the changed parts) |
  | song stopped | 45 % | 14 % (almost all of it is the POKEY emulation keeping the sound running) |

## Linux: let RITMO have the sound card

On Linux, programs that keep running in the background and hold the audio output take processor time and make the sound server mix and resample one more stream. One you may not know you have is **FluidSynth**, a MIDI synthesizer that some distributions (Debian among them) install together with the General MIDI sound fonts and **start at every login**, playing nothing. RITMO does not need it: it only *receives* MIDI, and a MIDI keyboard goes straight to RITMO without it. While you make music with RITMO, stop it (and other synthesizers or players you are not using):

```bash
systemctl --user stop fluidsynth      # until the next login
systemctl --user mask fluidsynth      # never start it again (undo with: systemctl --user unmask fluidsynth)
```

`systemctl --user disable` is not enough when the distribution enables the service for all users; `mask` needs no root. If the sound still crackles, start RITMO with `RMT_AUDIO_DEBUG=1` to see the late audio ticks and the underruns, and try a larger buffer with `RMT_AUDIO_BUFFER_MS=20`.
